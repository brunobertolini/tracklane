The browser and the server are **two libraries**. They share no runtime and no state: only the
vocabulary below, which is what makes `purchase` mean the same thing on both sides.

## The vocabulary

### `EventData`

What the business says happened, spelled the way GA4 spells it. The bag stays open: a business
measures things this vocabulary does not name.

### `UserData`

Who the person is. One identifier, translated into each vendor's own name. Values stay raw:
hashing is a field format each vendor defines, applied inside its adapter.

<AutoTypeTable path="../../packages/tracklane/src/vocabulary.ts" name="UserData" />

### `ConsentState`

Google's signals, adopted verbatim. Every other vendor receives a collapse of these, never an
expansion. An absent signal produces no key.

<AutoTypeTable path="../../packages/tracklane/src/vocabulary.ts" name="ConsentState" />

### `TrackingError`

The one diagnostic channel. Its `message` never carries event contents.

<AutoTypeTable path="../../packages/tracklane/src/vocabulary.ts" name="TrackingError" />

### `VendorResponseError`

What a server provider throws when the vendor's endpoint refuses the send, and what you find on
`TrackingError.cause` for that case. It carries the vendor's own answer, which is the part a
status code cannot tell you. Read it with `isVendorResponseError`, never `instanceof`, and read
[Why the vendor refused](/docs/installation#why-the-vendor-refused) before logging `body`.
